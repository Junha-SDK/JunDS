# No-Code Personas — End-to-End Scenarios

- **Slug:** `no-code-personas`
- **Status:** draft
- **Owner:** Junha (goodjunha@gmail.com)
- **Last updated:** 2026-04-30

## Goal

JunDS 노코드 프레임워크의 설계가 **실제 비개발자 사용자**의 시나리오를
온전히 처리하는지 검증하기 위한 페르소나 묶음. 다섯 개의 대표 사용자가 "처음
열어본 순간"부터 "도메인에서 라이브"까지 도달하는 과정을 한 번에 끊김 없이
설명한다. 이 시나리오는 [`no-code-framework-phase-0`](./no-code-framework-phase-0.md)
의 스키마/렌더러 분리부터 Phase 5(협업·게시) 까지의 기능 우선순위를 매기는
**유저 스토리의 단일 출처**다.

각 페르소나는 다음 다섯 항목을 가진다:

- **누구** — 직군, 기술 수준, 이미 가진 도구.
- **목표** — 사이트로 풀고 싶은 한 문장의 문제.
- **시작 자산** — 손에 들고 들어오는 것 (텍스트 메모, 사진 폴더, 엑셀 등).
- **End-to-end flow** — 빌더에 들어와서 게시까지 클릭 단위 여정.
- **결정적 디테일** — 이 페르소나가 막히지 않으려면 빌더가 반드시 갖춰야
  하는 UX 조건.

## Scope

- In scope:
  - 다섯 페르소나의 시나리오 + 각 단계가 의존하는 빌더 기능 매핑.
  - 각 페르소나가 **첫 30분**, **첫 하루**, **첫 일주일** 시점에 도달해야 하는
    상태.
  - 시나리오에서 도출된 Phase 1~5 의 **블로킹 기능 목록**.
- Out of scope:
  - 시각 디자인 무드보드 (별도 디자인 문서).
  - 가격/플랜 정책.
  - 마켓플레이스 템플릿 큐레이션 정책.

## Personas

### P1 — 카페 사장 민지 (랜딩 페이지)

- **누구.** 35세 카페 운영. 노트북은 매장에서 메뉴 인쇄·정산용. 코드 경험
  전혀 없음. 인스타그램 운영은 능숙. 노션은 못 다룸.
- **목표.** "카페 위치/영업시간/메뉴 사진 한 장짜리 사이트"를 일주일 안에
  도메인에 띄우고 싶다.
- **시작 자산.** 카메라 롤의 사진 12장, 메모 앱에 적은 영업시간/주소.
- **End-to-end flow.**
  1. `create-junds my-cafe` 가 아닌 **웹 빌더 도메인에 접속**해 "카페" 템플릿
     카드를 클릭. (Phase 5 마켓 또는 Phase 0 로컬 템플릿)
  2. 첫 화면: 히어로 섹션의 사진을 클릭 → 자기 사진 12장을 드래그앤드롭으로
     업로드 → 슬라이더 자동 구성. (Phase 4 자산 관리, Phase 0 Carousel)
  3. "오시는 길" 섹션의 주소 텍스트를 클릭하면 인플레이스 편집 → 지도가 자동
     주소 검색으로 위치 갱신. (Phase 2 Map composite + bindings)
  4. "영업시간" 카드 안의 표를 더블클릭 → 엑셀처럼 셀 수정. (Phase 0
     `InlineEdit`, 이미 라이브러리에 존재)
  5. 우상단 "공개" 버튼 → 무료 서브도메인 (`mycafe.junds.app`) 자동 발급. 도메인
     필드 비워두면 그대로 게시. (Phase 4)
- **결정적 디테일.**
  - **빈 캔버스를 절대 보여주지 않는다.** 첫 화면은 항상 6개 템플릿 카드.
  - **prop 이름 노출 금지.** `variant: "primary"` 가 아니라 "이 버튼을
    강조하기" 라는 한국어 라벨.
  - **모든 텍스트는 더블클릭 = 인플레이스 편집.** 별도 사이드패널 강제 X.
  - 사진 업로드는 드래그 한 번 = 끝. 리사이즈/포맷 변환은 자동.
  - **공개 버튼은 한 클릭.** 도메인 입력은 옵션이며 빈 값이면 자동 발급.

### P2 — 1인 작가 도윤 (블로그)

- **누구.** 28세 에세이 작가. 텍스트는 잘 쓰지만 마크다운까지가 한계. 이미
  Substack/브런치 사용 경험. 각주/인용 표기에 민감.
- **목표.** 자기 글을 한 페이지에서 읽기 좋은 타이포로 보여주고, 새 글을 쓰면
  자동으로 목록에 올라가게 하고 싶다.
- **시작 자산.** 워드 문서 30개 (또는 노션 export).
- **End-to-end flow.**
  1. "블로그" 템플릿 선택 → `포스트` 라는 **데이터 컬렉션**이 자동 생성됨
     (Phase 2 DataSource).
  2. "글 쓰기" 메뉴 클릭 → `RichTextEditor` (이미 patterns 에 존재) 가 풀스크린
     으로 열린다. 마크다운 단축키 + 슬래시 명령(`/인용`, `/이미지`) 지원.
  3. 저장하면 `posts` 컬렉션에 row 가 추가되고, 홈 페이지의 글 목록은
     `bindings: { source: "posts", orderBy: "publishedAt desc" }` 로 자동 갱신.
  4. 각 글 상세 페이지는 빌더에서 한 번만 만들고 `route: "/blog/[slug]"` 로
     템플릿화 (Phase 1 동적 라우트).
  5. 도메인 연결은 카페 사장 민지와 동일.
- **결정적 디테일.**
  - **글쓰기 흐름은 빌더와 분리된 모드여야 한다.** 작가는 캔버스를 보고 싶어
    하지 않는다 — 단지 "쓴다"의 경험만.
  - **타이포그래피 토큰 노출.** 본문 폭, 행간, 글자 크기를 슬라이더로 미세
    조정 (이미 `density`/`spacing` 토큰 시스템 존재).
  - **퍼블리시 vs 임시저장 두 상태.** 임시저장된 글은 사이트에 안 보이지만
     URL 만 알면 미리보기 가능 (Phase 4 의 preview URL).
  - 인용/각주는 RichTextEditor 의 슬래시 명령으로만 — 마크다운 모드는
     숨겨두지만 살아 있다.

### P3 — 핸드메이드 셀러 수아 (작은 쇼핑몰)

- **누구.** 31세, 도자기 공예 작가. Smartstore 에서 판매 중이지만 자체 사이트로
  브랜드를 만들고 싶어함. 엑셀로 재고 관리. 코드 모름.
- **목표.** 제품 12종, 사진 + 가격 + 재고 + 결제 까지 가능한 쇼핑 페이지.
- **시작 자산.** 엑셀 파일 (제품명/가격/재고/사진URL), Stripe 계정.
- **End-to-end flow.**
  1. "쇼핑몰" 템플릿 선택 → 시작 모달이 "엑셀 파일을 끌어다 놓으세요" 라고
     안내. (Phase 2 DataSource — `static` kind 의 빠른 import)
  2. 엑셀을 드롭하면 컬럼이 자동 매핑되고 (제품명 → `name`, 가격 → `price`),
     매핑이 어색한 컬럼만 수동 조정.
  3. 제품 카드 그리드는 `BentoGrid` 또는 `SimpleGrid` 위에 `Card` 가 데이터
     반복 (Phase 2 의 `<ForEach source="products">` 노드).
  4. "결제" 버튼은 액션 그래프에서 `kind: "callApi"` → Stripe Checkout 어댑터
     (Phase 2 의 사전 통합).
  5. 주문은 내장 KV (Phase 2) 에 쌓이고 "주문 관리" 라는 인터널 페이지에서 표로
     본다 (DataTable 패턴 활용).
- **결정적 디테일.**
  - **엑셀/CSV 임포트가 가장 큰 진입 장벽 제거 수단.** 컬럼 추론은 휴리스틱
    + 한국어 헤더(가격/재고/이름) 사전.
  - **재고 0 = 자동 "품절" 표시.** 사용자가 조건부 노출을 코드 없이 표현
     해야 하므로, prop 옆 `🔗` 옵션에 "조건부 표시" 가 일급으로 있어야 함.
  - **Stripe 등 결제 어댑터는 사전에 노드로 제공.** 사용자는 API 키만 한 번
     붙여 넣는다.
  - **"주문이 들어오면 이메일" 같은 자동화**는 Phase 2 액션 그래프의 첫 사용
     사례. (`kind: "sendEmail"` 노드 + Resend 어댑터)

### P4 — 사내 운영 매니저 지호 (어드민 대시보드)

- **누구.** 29세, 스타트업 운영팀. SQL 약간 만질 수 있고 Retool 을 본 적 있음.
  사내 데이터 시각화를 만들고 싶어함.
- **목표.** Postgres 의 `users`/`orders` 테이블을 표/차트로 보여주는 사내
  대시보드. 검색/필터/CSV 내보내기 필수.
- **시작 자산.** Postgres 연결 정보, 사내 SSO.
- **End-to-end flow.**
  1. "대시보드" 템플릿 → DataSource 추가 → "Postgres" 선택 → 연결.
  2. 빌더가 자동으로 테이블 목록을 가져와 사이드바에 표시. 끌어 놓으면 즉시
     `DataTable` (이미 25 기능 보유) 가 그려진다.
  3. 헤더에 `FilterBar` 추가 → 컬럼별 필터 자동 생성. "CSV" 버튼은 기본 내장.
  4. 별도 페이지에 `MetricCard` 4개 + `MiniChart` 를 끌어다 놓고 각각 SQL
     집계 쿼리에 바인딩 (Phase 2: SQL 입력 필드 + 결과 타입 추론).
  5. 게시는 외부에 공개하지 않고 SSO 로 잠금. (Phase 4 의 access control)
- **결정적 디테일.**
  - **DataTable 25 기능이 이 페르소나의 킬러 기능.** 외부 BI 와의 차별점.
  - **SQL 쿼리는 안전한 read-only.** 빌더 측에서 `SELECT` 외 거부.
  - **결과 스키마 추론.** 컬럼 타입을 자동 추론해서 `prop` 매핑이 자동.
  - **SSO/권한.** 게시된 페이지가 익명 접근 차단을 한 토글로 켤 수 있어야 함.

### P5 — 동네 미용실 원장 혜린 (예약 페이지)

- **누구.** 42세, 미용실 원장. 카카오톡 채널로 예약 받는 중. 노션도 어렵다고
  느낌. 모바일이 주 디바이스.
- **목표.** 손님이 시술/시간을 고르고 휴대폰 번호를 남기면, 원장 휴대폰에 알림이
  오는 예약 페이지.
- **시작 자산.** 시술 메뉴(=가격표) 사진 한 장, 자기 휴대폰 번호.
- **End-to-end flow.**
  1. 모바일 빌더(반응형 모드) 에서 "예약" 템플릿 선택. (Phase 1 모바일 편집
     UX — 데스크톱 한정이면 이 페르소나가 막힌다.)
  2. 사진 가격표를 OCR 로 끌어와서 시술 목록 폼이 자동 생성 (Phase 5 의 옵셔널
     ML 기능 — 막히면 수동 입력 fallback).
  3. 폼은 `Stepper` (이미 존재) 로 시술 → 시간 → 연락처 3단계.
  4. 제출 시 액션 그래프: `kind: "sendSms"` (Phase 2 어댑터, 또는 알림톡 연동)
     + `kind: "createRow"` (예약 컬렉션 저장).
  5. 자기 휴대폰에서 사이트 미리보기 QR 을 찍어 즉시 확인. (Phase 0 의 미리보기
     URL 기능)
- **결정적 디테일.**
  - **모바일 우선 빌더.** 모든 핵심 동작이 터치 한 손가락으로 끝나야 함.
    드래그앤드롭은 가능하면 드롭다운/리스트로 대체.
  - **휴대폰 알림은 일급.** SMS/카카오 알림톡 어댑터 사전 통합.
  - **달력/시간대 처리는 라이브러리가 책임.** 패턴 `Calendar` + `Stepper`
    이미 존재.
  - **관리자 화면 = 사이트의 한 페이지.** 별도 앱이 아니라 빌더가 만든 페이지에
    `route: "/admin"` + 잠금. 원장은 한 곳에서 다 본다.

## Cross-cutting requirements (다섯 페르소나 공통)

- 첫 30분 안에 **눈에 보이는 결과(공개 가능한 미리보기 URL)** 를 손에 쥐어야
  한다. 이게 첫 이탈 지점.
- 모든 사용자 노출 라벨은 **한국어 우선**. 영어 prop 이름은 보이지 않는다.
- 실수 복구가 항상 1번 동작 안에 있다 — 무한 Cmd+Z + 7일 자동 스냅샷.
- 결제/이메일/SMS/지도/달력 5개 어댑터는 **사전 통합**. "API 키 붙여 넣기" 한
  단계로 끝나야 함.
- "코드를 보고 싶다" 는 사용자에게는 항상 코드 export 가 살아 있다 (락인 우려
  완화).

## Phase mapping

| 페르소나 | Phase 0 (스키마) | Phase 1 (다중 페이지) | Phase 2 (데이터·액션) | Phase 3 (AI) | Phase 4 (게시) | Phase 5 (협업) |
| --- | --- | --- | --- | --- | --- | --- |
| P1 카페 민지 | ✓ | ✓ | △ (지도 정도) | — | ✓ | — |
| P2 작가 도윤 | ✓ | ✓ (동적 라우트) | ✓ (collection) | ○ (글 다듬기) | ✓ | — |
| P3 셀러 수아 | ✓ | ✓ | ✓ (CSV·결제·이메일) | ○ (제품 설명) | ✓ | — |
| P4 매니저 지호 | ✓ | ✓ | ✓ (Postgres·SQL) | △ | ✓ (SSO) | △ |
| P5 원장 혜린 | ✓ | ✓ | ✓ (SMS) | △ | ✓ (모바일 미리보기) | — |

✓ = 필수, ○ = 가치 큼, △ = 있으면 좋음, — = 미사용
